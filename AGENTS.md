# AGENTS.md

lightyear is an image processing platform. Users upload images and describe the output once as `ImageOptions`. A Go API and orchestrator schedule jobs, and a Rust worker processes them with libvips. A browser sandbox runs the same libvips through wasm-vips. The design docs are in `docs/` (Chinese); start at `docs/architecture/overview.md`.

## Guardrails

- `.env` points at **shared cloud services** (Neon Postgres, Upstash Redis, R2). Run tests, migrations and binaries only against local services, with the variables set explicitly on the command line.
- Go database tests read `TEST_DATABASE_URL`. Point it at a disposable local Postgres; without it, those tests are skipped.
- `go run ./server/cmd/migrate -reset` drops every table. The user runs it, never an agent.
- Keep `rust-toolchain.toml` on nightly.

## Done means

- `task check` passes. It covers Go build, cargo check, vue-tsc, and whether the schema and TS types are up to date.
- Tests for each area you touched pass:
  - Go: `go test ./server/...` with `TEST_DATABASE_URL` set.
  - Rust: `cargo test --workspace`. It needs `cjxl` and `djxl`.
  - Image behavior: also run `task test:fixtures` and `task test:consistency`.
- UI changes have been viewed in a browser (`task web`, port 3000).
- `task doctor` lists the toolchain (libvips ≥ 8.17, libavif ≥ 1.1, cjxl/djxl, Node ≥ 23.6).

## Gotchas

- libvips silently ignores an unknown option name. To prove an encoder or loader option has an effect, read the output back in a test and check it.
- `thumbnail` always outputs 8-bit. Sources deeper than 8-bit take the `full_depth` path in `compute-imageops`.
- wasm-vips runs under Node (`node scripts/consistency.ts`), not Bun, which hangs on its threads. It cannot do HEIC, and it cannot read JXL files that carry Exif.
- `scripts/fixtures/quality/` is generated by `scripts/fixtures/generate_quality_fixtures.sh`. Regenerate with the script instead of editing the files.
