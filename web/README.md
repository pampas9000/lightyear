# Web

Nuxt 4 frontend for `lightyear`: the product UI, the thin API client and proxy, and the in-browser WASM transcoding sandbox.

Contracts and behavior live in the docs site: [Getting started](../docs/getting-started.md), [HTTP API](../docs/contracts/http-api.md), [WASM contract](../docs/contracts/wasm.md), [Known limitations](../docs/compute/limitations.md).

## Stack

- Nuxt 4 (`srcDir: app`) + Vue 3.5 + Vite
- Tailwind CSS 4 (CSS-first, no `tailwind.config`)
- shadcn-nuxt + reka-ui primitives
- @nuxtjs/i18n with 6 locales (`en-US` default, `zh-Hans`, `zh-Hant`, `ja-JP`, `de-DE`, `fr-FR`)
- Uppy (S3 multipart uploads), `@jsquash/jxl`, VueUse

## Responsibilities

- user interface, upload flow, task submission and status views
- API client with auth token handling and error-code mapping
- transparent proxying of `/api/**` to the Go backend
- local WASM processing in a Web Worker (no Canvas intermediate)

Out of scope: scheduling, persistence, auth decisions, FFI.

```text
│   └── assets/styles/main.css  # Tailwind 4 @theme tokens

```

## Integration surface

- **API**: `useApi` creates a `$fetch` client with `baseURL: /api`; the Nitro route rule proxies `/api/**` to `http://localhost:8080/api/**`. Auth uses `auth_token` cookies plus `Authorization: Bearer` and opens the auth modal on 401.
- **WASM**: `useComputeWasm` builds module URLs from `app.baseURL` and dynamically imports `wasm/compute_wasm.js` inside `compute.worker.ts`. Pixel data moves as transferable `Uint8Array`s; JXL goes through `@jsquash/jxl`, including the lossless JPEG → JXL frequency-domain bypass.
- **UI settings**: `TranscodeSettings.vue` renders the color pipeline presets (“keep original look” vs “standard SDR”), depth, chroma, ICC policy and strict mode; `TaskRetryDrawer.vue` reuses it for retry-with-overrides.

## Development

From the repo root:

```bash
task bootstrap       # bun install
task web             # or: bun run dev:web   (:3000)
task check:web       # or: cd web && bunx vue-tsc -b --noEmit
task build:web       # builds WASM first, then the Nuxt bundle
```

`web/public/wasm` is generated by `bun run build:compute:wasm` and is not checked in.

## Current status

### Known gaps

- No runtime config/env variables are consumed yet; API base URL is fixed through the Nitro proxy
- `app/lib/api/` does not exist — the client lives in `composables/useApi.ts`
- No frontend test tooling (typecheck only)
- Wide-gamut output from the sandbox is untagged (see [Known limitations](../docs/compute/limitations.md))
